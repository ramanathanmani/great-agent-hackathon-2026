# FreshVoice Constitution

The non-negotiable principles every spec, design, and change in this repo must respect.
If a spec needs to break one of these, the spec must say so explicitly and the
constitution is amended in the same PR.

## 1. Spec before code
No feature or behavioural change lands without a spec in `specs/NNN-slug/`
whose `requirements.md` is at least `Status: Approved`. Bug fixes that restore
already-specified behaviour may skip a new spec but must reference the
requirement they restore.

## 2. Single source of truth
`codemix.js` is the only hand-edited engine. `codemix.cjs` is generated by
`scripts/build-cjs.js` and must never be edited by hand (CI drift check enforces this).

## 3. Degrade, never fail
Every external dependency (Gemini, ElevenLabs, Freshdesk, any future backend)
has a deterministic offline fallback. A missing key, 429, 503, or malformed
response must produce a usable result, not a blank screen or thrown error.

## 4. Zero-dependency core
The offline engine and the decision-policy layer run on plain Node >= 18 with
no runtime npm dependencies. Only `mcp-server/` may add dependencies.

## 5. Honest numbers
Every metric published in README, SUBMISSION, ARCHITECTURE, or a pitch must:
- name the dataset it was measured on (tuned / extended / blind / synthetic),
- be reproducible from a command in the repo, and
- distinguish *measured* results from *structural guarantees* (results that are
  true by construction).

## 6. Secrets stay out
No API keys in the repo or in generated artifacts. Server-side keys come from
environment variables; browser-held keys are a demo-only concession and must be
labelled as such.

## 7. Traceability
Every requirement has acceptance criteria and a `Verify:` line pointing at a
test/script that proves it, or at the pending task that will add one.
Every task references the requirement(s) it satisfies. `npm run check:specs`
enforces this in CI.
